# 第二步：怎么让 Codex 看懂你的参考图

小白最容易犯的错误是只说：

```text
按照这张图做。
```

这句话太模糊。Codex 不知道你到底喜欢的是颜色、布局、动效、字体、氛围，还是某个卡片。

正确方法是拆成 6 个问题。

## 1. 我喜欢它的氛围吗？

例子：

```text
我喜欢它的深空、安静、神秘、科技感。
```

这会影响背景、颜色、光效和整体节奏。

## 2. 我喜欢它的布局吗？

例子：

```text
我喜欢它一屏一个重点，主视觉很大，文字很少。
```

这会影响页面结构。

## 3. 我喜欢它的组件吗？

例子：

```text
我喜欢它的卡片像任务档案，有细边框、发光、暗色玻璃质感。
```

这会影响按钮、卡片、弹窗、导航。

## 4. 我喜欢它的移动端吗？

例子：

```text
我喜欢它手机端是竖长卡片，适合一张一张滑动。
```

这会影响手机端布局。

## 5. 哪些地方不能照抄？

例子：

```text
不要照抄英文标题、宇航员图片、行星位置和原始排版。
```

这能避免版权风险，也能让项目更原创。

## 6. 它要怎么变成我的项目？

例子：

```text
把空间探索改成高中生物科学史探索。
把行星页面改成教材模块页面。
把宇航员任务档案改成科学家详情档案。
```

这是最关键的一步：参考图只是“感觉”，你的项目才是“内容”。
